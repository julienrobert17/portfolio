## 1. Ce que fait la phase

Le label dépose ses fichiers d'origine dans le Studio ; le site n'a plus aucun média dans le dépôt.

1. **Schémas du Studio** (`studio/schemas/`) : `imagesDerivees` porte une série de largeurs (`tailles` : largeur, hauteur, AVIF, WebP) en plus de la plus grande ; `traitement` porte une `empreinte` (référence du fichier d'origine au dernier traitement, cachée) ; `couleursExtraites` gagne le contraste du texte clair sur l'accent ; la piste gagne `extraitDuree`, `sonie` (LUFS mesurés), `bpm` (estimé) et `extraitProvisoire` ; l'artiste gagne `traitement` et `portraitOptimise`. Tout est en lecture seule pour les éditeurs, dans l'onglet Automatique. Studio déployé.
2. **Bibliothèque** (`scripts/g2g-lib.ts`) : `deriverImage` (AVIF et WebP en mémoire pour chaque largeur de 320 à 1600 px que la source permet, ratio conservé, sans recadrage, chaque fichier sous 300 kB, la qualité descend tant qu'il faut), `extraireCouleurs` (reprise à l'identique de `g2g-couleurs.ts`, disque inscrit, 4 bits par canal) et `estimerBpm` (enveloppe d'attaques à 43 trames par seconde, autocorrélation de 70 à 180 BPM, préférence 100 à 150, interpolation parabolique du pic). `exporterImage` (tuile) les réutilise.
3. **Pipeline** (`scripts/g2g-pipeline-sanity.ts`) : pour chaque document publié (sortie, soirée, artiste) dont le fichier d'origine a une empreinte différente de celle du dernier traitement, et pour chaque piste avec un `extraitBrut` : état « en cours » → téléchargement de l'original → dérivation → téléversement des dérivés comme fichiers Sanity → écriture des champs, « prêt » avec date et empreinte, ou « refusé » avec raison. Règles du brief §7 : une sortie non parue refuse l'extrait ; 60 s dès 30 % du morceau (ou tout le fichier s'il est plus court), fondus de 2 s, MP3 192 kbps à −14 LUFS par `encoderMp3Normalise` (mesure ebur128, limiteur, jusqu'à six passes), sonie mesurée après coup, durée par ffprobe, BPM estimé. Les anciens dérivés sont supprimés ; le brouillon du document, s'il existe, reçoit le même patch, pour que la publication suivante ne perde pas les champs. `--sec` ne modifie rien, `--tout` retraite tout, `--rapport` écrit le tableau Markdown. Jeton : `SANITY_PIPELINE_TOKEN`, sinon la session de la CLI en local.
4. **Où ça tourne** : Action GitHub `.github/workflows/g2g-pipeline-medias.yml`, toutes les 15 minutes (le dépôt est public : minutes illimitées ; sans empreinte changée, le script ne fait rien), à la demande, ou par `repository_dispatch` de type `g2g-medias`. ffmpeg et ffprobe du runner Ubuntu, `npm ci --ignore-scripts`, rapport en artefact 7 jours. Sans le secret `SANITY_PIPELINE_TOKEN`, le job s'arrête avec un avertissement, sans échouer. Les patches déclenchent le webhook de publication existant : le site est revalidé comme pour toute publication (mesuré à 7,4 s en 7.3).
5. **Le site** : requêtes GROQ (`sanity/requetes.ts`) avec `pochetteOptimisee`, `flyerOptimise`, `portraitOptimise` (URL des fichiers par largeur), `couleurs`, et par piste `extrait` (URL du MP3), `extraitDuree`, `bpm`, `extraitProvisoire` ; types régénérés ; adaptateur vers `ImageSite`, `Couleurs`, `Extrait` dans `content/types.ts`. `Photo` prend une image du site (srcset AVIF et WebP depuis `cdn.sanity.io`, `alt` saisi par le label prioritaire sur le texte construit) ; `couleursCassette`, `couleursBandeau`, `pisteJouable`, `catalogueLecteur` lisent les couleurs et les extraits de la sortie ; la Media Session reçoit l'URL de la vignette 320 px ; la page de rendu de la tuile lit GTGR05 dans Sanity ; deux `preconnect` vers le CDN (clair pour les images, CORS pour l'audio). Aucun composant d'affichage n'a changé de rendu.
6. **CORS** : le CDN d'un dataset privé répond **403 à toute requête portant `Origin`** tant que l'origine n'est pas déclarée dans le projet (constaté par `curl` : 200 sans `Origin`, 403 avec). Or `<audio crossOrigin="anonymous">` (obligatoire pour l'analyseur du spectre) envoie `Origin`. Origines ajoutées (`sanity cors add … --no-credentials`) : production Vercel, preview de la branche, `localhost:3999`. **Le domaine final du label devra y être ajouté.** Vérifié ensuite : `access-control-allow-origin` renvoyé, `accept-ranges: bytes` sur les MP3.
7. **Correction du bloc 7.3b, trouvée par Lighthouse sur la preview** : avec `data-js` posé à l'hydratation (et non plus avant le premier paint par le script en ligne), la géométrie du rendu serveur différait de celle du rendu hydraté (rangée des commandes `display: none` puis affichée sur desktop, navigation repliée puis bouton menu sur mobile, marges de `.g2g-page` conditionnées à `data-js`) : **CLS 0,087 à 0,121 sur les quatre pages mesurées, contre 0,000 en 7.3**. Ce que j'avais présenté en 7.3b comme un « enrichissement progressif correct » était un décalage de mise en page mesurable. Corrigé dans `g2g.css` : les commandes `.g2g-js` gardent leur place avant l'hydratation (`visibility: hidden` au lieu de `display: none`), toutes les règles de géométrie sont inconditionnelles, et les variantes sans script (commandes retirées, navigation sur sa ligne, pièces de collage visibles d'emblée) passent par la media query native `@media (scripting: none)` (Chrome 120, Safari 17, Firefox 113) : un mécanisme du navigateur, sans balise injectée, qui vaut par tout chemin d'arrivée. `data-js` ne sert plus qu'à révéler les commandes une fois React monté. Résultats après correction en §3.
8. **Retiré** : `content/{artists,events,releases,label,index,medias,extraits,couleurs}.ts` (seuls `types.ts` et `presets.ts` restent), `content/groove-to-grave/media/` (originaux publics, manifeste du label, rapport) et `sources.json`, `public/experience/groove-to-grave/img/` et `audio/` (hors tuile et textures du mur : 7,6 + 7,2 Mo de moins dans le dépôt), scripts `g2g-media`, `g2g-couleurs`, `g2g-fetch-media`, `g2g-extraits`, `g2g-export-sanity`, `g2g-planche-da`, `g2g-logos` (leurs sorties sont commitées ou dans Sanity ; l'historique git les garde), helpers de manifestes dans `g2g-lib`. Brief §4.1 et §7 mis à jour.

## 5. Arbitrages

- **Action GitHub planifiée** plutôt que webhook Sanity → `repository_dispatch` direct : le relais exigerait un jeton GitHub stocké dans la configuration du webhook chez Sanity, hors des emplacements que tu as autorisés (`.env.local`, `studio/.env.local`, Vercel, secrets GitHub). Le `repository_dispatch` reste branché dans l'Action pour le jour où un relais (route Vercel avec un jeton GitHub dans ses variables) serait voulu ; latence actuelle : jusqu'à 15 minutes, visible dans le Studio par l'état « en attente ».
- **Dérivés produits par le pipeline et stockés comme fichiers Sanity** plutôt que transformations à la volée du CDN d'images : garde la règle « jamais recadrée, AVIF et WebP sous 300 kB » sous notre contrôle, et le site ne dépend d'aucune API de transformation.
- **Audio servi en direct depuis le CDN** (CORS déclaré) plutôt qu'une réécriture Next en proxy : pas de bande passante Vercel doublée, `Range` géré par le CDN ; à surveiller sur Safari (non testé ici : pas d'automatisation Safari disponible).
- **Boucles provisoires dans Sanity** : le site continue de jouer quelque chose tant que le label n'a pas déposé de fichiers ; marquées « extrait provisoire » dans la bande défilante comme avant, remplacées par le pipeline dès qu'un extrait brut est déposé sur la piste.
- **Alt du label prioritaire** dans `Photo` : le champ obligatoire du Studio sert à quelque chose ; le texte construit par la page reste un repli.
